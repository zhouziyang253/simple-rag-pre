NIMBUSFLOW SDK DEVELOPER DOCUMENTATION
Document ID: NF-DOC-2024-11-PLAIN
Version: 3.4.0
Last updated: 2024-11-10
Maintained by: NimbusFlow Platform Engineering
Audience: Application developers, data engineers, site reliability engineers

1. OVERVIEW

NimbusFlow is a Python SDK for building and operating data pipelines. It provides a declarative pipeline API, a runtime scheduler, connector adapters, retry policies, metrics hooks, and a command-line interface. The SDK targets batch and micro-batch workloads. It does not provide a general-purpose distributed compute engine. Execution is delegated to supported executors.

The SDK is organized into these packages:

nimbusflow.core: pipeline definition, task graph, context, configuration.
nimbusflow.io: readers, writers, file formats, serialization.
nimbusflow.connectors: database, HTTP, message queue, object storage connectors.
nimbusflow.retry: retry policies, backoff strategies, circuit breakers.
nimbusflow.metrics: counters, gauges, timers, exporters.
nimbusflow.cli: command-line interface.
nimbusflow.testing: test harness, fixtures, fake connectors.

The current stable release is 3.4.0, released on 2024-10-28. The previous stable release was 3.3.2, released on 2024-08-15. Version 3.2.x is in maintenance mode and receives security fixes only. Version 2.x reached end-of-life on 2024-06-30 and receives no further fixes.

NimbusFlow requires Python 3.9 or newer. Python 3.8 is not supported in 3.4.0. The SDK is tested on CPython 3.9, 3.10, 3.11, and 3.12. PyPy 3.10 is supported experimentally. PyPy 3.9 is not supported.

2. INSTALLATION

Install from PyPI:

pip install nimbusflow==3.4.0

Install optional connector dependencies:

pip install "nimbusflow[postgres,http,s3]==3.4.0"

The base package includes nimbusflow.core, nimbusflow.io, nimbusflow.retry, nimbusflow.metrics, and nimbusflow.cli. Connector extras are separate because they pull in third-party drivers.

Available extras:

postgres: PostgreSQL connector, requires psycopg>=3.1.
mysql: MySQL connector, requires pymysql>=1.1.
http: HTTP connector, requires httpx>=0.27.
s3: S3-compatible object storage, requires boto3>=1.34.
kafka: Kafka connector, requires confluent-kafka>=2.3.
redis: Redis connector, requires redis>=5.0.
all: installs all supported extras.

The all extra does not include kafka on Python 3.12 because confluent-kafka wheels for Python 3.12 are not published for all platforms. Install kafka separately on Python 3.12 after confirming wheel availability.

NimbusFlow does not bundle a database driver by default. Installing nimbusflow without extras gives the core runtime but no database connectors. Importing nimbusflow.connectors.postgres.PostgresConnector without the postgres extra raises MissingDependencyError.

3. QUICKSTART

from nimbusflow.core import Pipeline, task
from nimbusflow.io import CsvReader, ParquetWriter

@task(retries=2, timeout=300)
def clean_rows(rows):
    return [r for r in rows if r.get("status") == "active"]

pipeline = Pipeline(name="active_users", schedule="0 2 * * *")

read = CsvReader(path="s3://bucket/users.csv")
write = ParquetWriter(path="s3://bucket/active_users.parquet")

pipeline.add(read >> clean_rows >> write)

if __name__ == "__main__":
    pipeline.run()

The >> operator composes stages. read >> clean_rows >> write creates a linear graph with three nodes. The scheduler executes nodes in dependency order. By default, a pipeline runs with a local executor using a thread pool of size 4. The default executor is not a distributed executor.

4. CORE CONCEPTS

4.1 PIPELINE

A Pipeline is a directed acyclic graph of tasks. It has a name, an optional schedule, default retry settings, and a context. Pipeline names must match ^[a-z][a-z0-9_]{2,63}$. Names are case-sensitive and must be lowercase. A pipeline name cannot start with a digit or an underscore.

Pipeline.run() executes the graph once. Pipeline.serve() starts a long-running scheduler that respects the schedule field. serve() is not available in nimbusflow.core on Windows. On Windows, use run() with an external scheduler.

4.2 TASK

A task is a callable decorated with @task. The decorator accepts:

retries: int = 0. Number of retries after the first failure.
timeout: int | None = None. Per-attempt timeout in seconds.
backoff: str = "exponential". One of "fixed", "linear", "exponential".
backoff_base: float = 1.0. Base delay in seconds.
backoff_max: float = 60.0. Maximum delay in seconds.
tags: list[str] | None = None. Arbitrary tags for metrics and filtering.
resources: dict[str, float] | None = None. Resource hints, not enforced by the local executor.

retries=2 means three total attempts: one initial attempt plus two retries. It does not mean two total attempts.

The default timeout is None, which means no per-attempt timeout. A pipeline-level max_runtime can still stop the whole run.

4.3 CONTEXT

Context carries run metadata and shared configuration. It is passed to tasks that declare a ctx parameter:

@task
def transform(rows, ctx):
    ctx.log.info("processing", count=len(rows))
    return rows

The context is injected by parameter name. A task parameter named ctx receives the Context object. A parameter named context does not receive it.

Context exposes:

ctx.run_id: str. Unique run identifier.
ctx.pipeline_name: str.
ctx.log: structured logger.
ctx.config: ConfigView. Read-only configuration view.
ctx.metrics: metrics client.

4.4 EXECUTORS

NimbusFlow ships with three executors:

LocalExecutor: thread pool, default size 4, default executor.
ProcessExecutor: process pool, default size 2, requires picklable tasks.
RemoteExecutor: submits to a NimbusFlow control plane, requires a control plane URL and token.

LocalExecutor is the default. ProcessExecutor is not supported on Windows for tasks that use the ctx parameter because the context contains a logger that is not picklable. RemoteExecutor requires NimbusFlow Enterprise and is not available in the open-source distribution.

The executor is selected with Pipeline(executor=...). An unknown executor name raises ValueError in Pipeline.__init__.

5. CONFIGURATION

Configuration is resolved in this order, from highest priority to lowest:

1. Explicit arguments passed to Pipeline(...) or connector constructors.
2. Environment variables prefixed with NIMBUSFLOW_.
3. A configuration file at ~/.nimbusflow/config.toml.
4. SDK defaults.

Environment variable names are uppercase and use underscores. For example, NIMBUSFLOW_DEFAULT_RETRIES=3 sets the default retry count for tasks that do not specify retries.

Supported environment variables:

NIMBUSFLOW_DEFAULT_RETRIES: integer, default 0.
NIMBUSFLOW_DEFAULT_TIMEOUT: integer seconds, default unset.
NIMBUSFLOW_LOG_LEVEL: one of DEBUG, INFO, WARNING, ERROR. Default INFO.
NIMBUSFLOW_METRICS_BACKEND: one of none, prometheus, statsd. Default none.
NIMBUSFLOW_CONTROL_PLANE_URL: string, required for RemoteExecutor.
NIMBUSFLOW_CONTROL_PLANE_TOKEN: string, required for RemoteExecutor.
NIMBUSFLOW_S3_ENDPOINT: string, optional.
NIMBUSFLOW_HTTP_TIMEOUT: float seconds, default 30.0.

NIMBUSFLOW_LOG_LEVEL accepts only uppercase values. Lowercase debug is ignored and falls back to INFO. This behavior is intentional.

The config file uses TOML. Example:

[defaults]
retries = 2
timeout = 600

[metrics]
backend = "prometheus"
port = 9091

Configuration keys in the file use lowercase snake_case. Environment variables override the file.

6. NIMBUSFLOW.IO: READERS AND WRITERS

6.1 CSVREADER

CsvReader(
    path: str,
    delimiter: str = ",",
    header: bool = True,
    encoding: str = "utf-8",
    chunksize: int | None = None,
)

CsvReader reads CSV files from a local path or an s3:// URI. If chunksize is None, the entire file is loaded into memory. For files larger than 512 MiB, set chunksize to avoid memory pressure. The default chunksize is None, not a streaming default.

CsvReader does not infer schema. All values are returned as strings unless a schema argument is passed to the pipeline stage. Schema inference is available in nimbusflow.io.schema.infer_schema but is not applied automatically.

6.2 PARQUETWRITER

ParquetWriter(
    path: str,
    compression: str = "snappy",
    row_group_size: int = 128_000,
    partition_by: list[str] | None = None,
)

Supported compression codecs are snappy, gzip, zstd, and none. The default is snappy. brotli is not supported in 3.4.0. Passing compression="brotli" raises UnsupportedCodecError.

partition_by creates Hive-style partitions. Partition columns are removed from the file body. If a partition column is missing from a row, the writer raises MissingPartitionValueError.

6.3 JSONREADER AND JSONWRITER

JsonReader supports newline-delimited JSON, also called NDJSON, and JSON arrays. The mode parameter accepts "ndjson" or "array". The default is "ndjson". JsonReader does not support JSON Lines with comments.

JsonWriter always writes NDJSON. It does not support writing a single JSON array. To produce an array, write NDJSON and convert downstream.

6.4 SERIALIZATION

nimbusflow.io.serialize provides to_bytes and from_bytes. Supported formats are json, msgpack, and pickle. pickle is disabled by default for security reasons. To enable it, set NIMBUSFLOW_ALLOW_PICKLE=1. Enabling pickle is not recommended for untrusted data.

7. NIMBUSFLOW.CONNECTORS

7.1 POSTGRESCONNECTOR

PostgresConnector(
    dsn: str,
    pool_size: int = 5,
    pool_timeout: float = 30.0,
    statement_timeout_ms: int | None = None,
    autocommit: bool = False,
)

PostgresConnector requires the postgres extra. It uses psycopg 3.x. psycopg2 is not supported in 3.4.0. If psycopg2 is installed and psycopg is not, the connector raises MissingDependencyError with a message naming psycopg>=3.1.

The default pool_size is 5. The default pool_timeout is 30.0 seconds. statement_timeout_ms is applied per connection via SET statement_timeout. If None, no statement timeout is set.

autocommit defaults to False. In autocommit mode, each statement commits immediately. In non-autocommit mode, the connector wraps a pipeline stage in a transaction and commits on success. A failed stage rolls back.

7.2 HTTPCONNECTOR

HttpConnector(
    base_url: str,
    timeout: float = 30.0,
    max_retries: int = 0,
    verify_tls: bool = True,
    headers: dict[str, str] | None = None,
)

HttpConnector uses httpx. The default timeout is 30.0 seconds. max_retries defaults to 0. HTTP-level retries are separate from task-level retries. If both are configured, task-level retries wrap the entire HTTP call, including connector-level retries.

verify_tls=False disables certificate verification. This is allowed but logs a warning at WARNING level. It is not recommended in production.

HttpConnector does not follow redirects by default. Set follow_redirects=True to enable redirect following. The maximum redirect count is 10. Exceeding it raises TooManyRedirectsError.

7.3 S3CONNECTOR

S3Connector(
    bucket: str,
    region: str | None = None,
    endpoint_url: str | None = None,
    multipart_threshold: int = 8 * 1024 * 1024,
    multipart_chunksize: int = 8 * 1024 * 1024,
)

S3Connector requires the s3 extra. The default multipart threshold is 8 MiB. The default multipart chunk size is 8 MiB. The minimum allowed chunk size is 5 MiB. Values below 5 MiB raise ValueError.

S3Connector supports S3-compatible endpoints via endpoint_url. It does not support Swift or Azure Blob directly. Use the HTTP connector or a custom adapter for those.

7.4 KAFKACONNECTOR

KafkaConnector(
    bootstrap_servers: str,
    group_id: str,
    auto_offset_reset: str = "earliest",
    enable_auto_commit: bool = False,
    max_poll_records: int = 500,
)

KafkaConnector requires the kafka extra. auto_offset_reset accepts "earliest", "latest", or "error". The default is "earliest". enable_auto_commit defaults to False. NimbusFlow commits offsets after a stage succeeds. max_poll_records defaults to 500.

The Kafka connector is not available on Python 3.12 in the all extra. Install kafka separately.

7.5 REDISCONNECTOR

RedisConnector(
    url: str,
    db: int = 0,
    socket_timeout: float = 5.0,
    max_connections: int = 10,
)

RedisConnector requires the redis extra. The default socket_timeout is 5.0 seconds. max_connections defaults to 10. Redis Cluster is supported only in nimbusflow.connectors.redis_cluster.RedisClusterConnector, not in RedisConnector.

8. NIMBUSFLOW.RETRY

8.1 RETRYPOLICY

RetryPolicy(
    max_attempts: int = 3,
    backoff: str = "exponential",
    base: float = 1.0,
    max_delay: float = 60.0,
    jitter: bool = True,
    retry_on: tuple[type[Exception], ...] = (Exception,),
)

max_attempts counts total attempts, not retries. max_attempts=3 means one initial attempt plus two retries. This differs from the @task(retries=...) parameter, where retries=3 means one initial attempt plus three retries.

This inconsistency is documented but not deprecated. The SDK team has stated that changing it would be a breaking change and is deferred to 4.0.

retry_on defaults to (Exception,), which retries all exceptions. To retry only specific exceptions, pass a tuple. retry_on=(ValueError,) retries only ValueError and its subclasses. KeyboardInterrupt and SystemExit are never retried, even if included in retry_on.

8.2 BACKOFF STRATEGIES

fixed: delay is always base.
linear: delay is base * attempt_number.
exponential: delay is base * 2 ** (attempt_number - 1), capped at max_delay.

Jitter is enabled by default and adds a random factor between 0.5 and 1.5 to the computed delay. To disable jitter, set jitter=False.

max_delay defaults to 60.0 seconds. A delay is never greater than max_delay, even with jitter.

8.3 CIRCUITBREAKER

CircuitBreaker(
    failure_threshold: int = 5,
    recovery_timeout: float = 30.0,
    half_open_max_calls: int = 1,
)

The circuit breaker opens after failure_threshold consecutive failures. The default is 5. It moves to half-open after recovery_timeout seconds. The default is 30.0. In half-open state, at most half_open_max_calls calls are allowed. The default is 1.

CircuitBreaker is not integrated with @task automatically. Wrap the callable manually or use nimbusflow.retry.with_circuit_breaker.

9. NIMBUSFLOW.METRICS

9.1 METRICS CLIENT

from nimbusflow.metrics import get_metrics

m = get_metrics()
m.counter("rows_processed", 1, tags={"pipeline": "active_users"})
m.gauge("queue_depth", 42)
m.timer("stage_duration", 1.23)

The default metrics backend is none, which means metrics are no-ops. Set NIMBUSFLOW_METRICS_BACKEND=prometheus to enable the Prometheus exporter. The Prometheus exporter listens on port 9091 by default. The StatsD exporter uses UDP port 8125 by default.

Prometheus metrics are exposed at /metrics on the configured port. The exporter does not support pushgateway mode in 3.4.0.

9.2 METRIC NAMING

Metric names must match ^[a-zA-Z_][a-zA-Z0-9_]*$. Dots and hyphens are not allowed. Invalid names raise InvalidMetricNameError. Names are case-sensitive.

Tags are converted to Prometheus labels. Tag keys must also match the metric name pattern. A tag key named pipeline-name is invalid. Use pipeline_name.

10. CLI

The CLI is available as nimbusflow after installation.

nimbusflow run path/to/pipeline.py
nimbusflow validate path/to/pipeline.py
nimbusflow list
nimbusflow logs --run-id RUN_ID

nimbusflow run executes a pipeline module. The module must expose a pipeline object. nimbusflow validate parses the module and checks the graph without executing it. nimbusflow list lists registered pipelines from the local registry. nimbusflow logs requires a control plane and is not available in local-only mode.

Global flags:

--config PATH: path to config file.
--log-level LEVEL: overrides NIMBUSFLOW_LOG_LEVEL.
--dry-run: validate only, do not execute.

--dry-run is equivalent to validate for run. It does not contact external systems.

Exit codes:

0: success.
1: validation error.
2: runtime error.
3: configuration error.
4: missing dependency.

11. ERROR CODES AND EXCEPTIONS

All SDK exceptions inherit from NimbusFlowError.

NimbusFlowError: base class.
ConfigurationError: invalid configuration.
MissingDependencyError: optional dependency not installed.
ValidationError: invalid pipeline graph or arguments.
UnsupportedCodecError: unsupported compression codec.
MissingPartitionValueError: partition column missing.
TooManyRedirectsError: HTTP redirect limit exceeded.
CircuitOpenError: circuit breaker is open.
RetryExhaustedError: all retry attempts failed.
RemoteExecutionError: control plane returned an error.

RetryExhaustedError wraps the last exception as __cause__. Inspect err.__cause__ for the original failure.

CircuitOpenError is raised immediately when the breaker is open. It is not retried by task-level retries unless explicitly included in retry_on.

13. MIGRATION NOTES: 2.X TO 3.X

13.1 REMOVED APIS

nimbusflow.core.Job: removed. Use Pipeline.
nimbusflow.core.run_job(): removed. Use Pipeline.run().
nimbusflow.io.CsvReader(infer_schema=True): removed. Use nimbusflow.io.schema.infer_schema explicitly.
nimbusflow.connectors.postgres.PsqlConnector: removed. Use PostgresConnector.
nimbusflow.retry.Retry: removed. Use RetryPolicy.

13.2 RENAMED PARAMETERS

Pipeline(jobs=...) becomes Pipeline(tasks=...).
@task(retry=...) becomes @task(retries=...).
CsvReader(sep=...) becomes CsvReader(delimiter=...).
PostgresConnector(conn_string=...) becomes PostgresConnector(dsn=...).
HttpConnector(retries=...) becomes HttpConnector(max_retries=...).

13.3 BEHAVIOR CHANGES

@task(retries=N) now means N retries after the first attempt. In 2.x, retry=N meant N total attempts.
The default executor changed from ProcessExecutor to LocalExecutor in 3.0.0.
The default CSV chunksize changed from 10000 to None.
The default metrics backend changed from statsd to none.
Pipeline.run() now returns a RunResult object instead of None.

13.4 DEPRECATED BUT STILL WORKING IN 3.4.0

Pipeline.add_job() is deprecated. Use Pipeline.add().
nimbusflow.metrics.StatsdClient is deprecated. Use get_metrics() with NIMBUSFLOW_METRICS_BACKEND=statsd.
CsvReader(encoding="latin-1") works but logs a warning. UTF-8 is recommended.

Deprecated APIs will be removed in 4.0.0. No removal date has been announced.

14. KNOWN LIMITATIONS

NimbusFlow does not provide exactly-once semantics for arbitrary connectors. Exactly-once depends on the connector and sink. The Postgres connector provides at-least-once delivery. Deduplication must be handled by the sink.

LocalExecutor does not enforce resource hints. resources={"cpu": 2} is advisory only.

ProcessExecutor is not supported on Windows for tasks with ctx.

RemoteExecutor requires NimbusFlow Enterprise. It is not in the open-source package.

The Kafka connector is not available on Python 3.12 in the all extra.

ParquetWriter does not support brotli compression in 3.4.0.

JsonWriter does not write JSON arrays.

HttpConnector does not follow redirects by default.

RedisConnector does not support Redis Cluster. Use RedisClusterConnector.

S3Connector does not support Azure Blob or Swift.

Schema inference is not automatic in CsvReader.

CircuitBreaker is not integrated with @task automatically.

Prometheus exporter does not support pushgateway mode in 3.4.0.

NIMBUSFLOW_LOG_LEVEL accepts uppercase only. Lowercase values fall back to INFO.

Pipeline names must be lowercase and cannot start with a digit or underscore.

15. SECURITY NOTES

pickle serialization is disabled by default. Set NIMBUSFLOW_ALLOW_PICKLE=1 to enable it. Do not enable it for untrusted data.

verify_tls=False disables certificate verification and logs a warning. It is not recommended in production.

Control plane tokens are read from NIMBUSFLOW_CONTROL_PLANE_TOKEN. Do not hard-code tokens in pipeline files.

The SDK does not redact secrets from logs. If a task logs a connection string, the secret appears in logs. Use ctx.config.redact() to redact known secret keys.

The HTTP connector does not strip Authorization headers on redirect by default. Set strip_auth_on_redirect=True if redirects to third-party hosts are possible.

16. PERFORMANCE TUNING

For CSV files larger than 512 MiB, set chunksize. The default None loads the whole file.

LocalExecutor default pool size is 4. Increase with Pipeline(executor=LocalExecutor(pool_size=8)) if tasks are I/O-bound.

ProcessExecutor default pool size is 2. Process startup overhead is significant for short tasks.

ParquetWriter default row group size is 128,000 rows. Smaller row groups increase file count and metadata overhead.

S3Connector default multipart threshold and chunk size are both 8 MiB. The minimum chunk size is 5 MiB.

HttpConnector default timeout is 30.0 seconds. Connector-level retries default to 0.

PostgresConnector default pool size is 5. Default pool timeout is 30.0 seconds.

KafkaConnector default max_poll_records is 500.

RetryPolicy default max_delay is 60.0 seconds. Jitter is enabled by default.

17. TESTING

nimbusflow.testing provides:

FakeCsvReader: in-memory CSV reader.
FakePostgresConnector: in-memory Postgres-compatible connector for simple queries.
run_pipeline(pipeline): executes a pipeline synchronously and returns RunResult.
assert_task_called(task, times=N): asserts call count.

FakePostgresConnector supports only SELECT, INSERT, and DELETE with simple WHERE clauses. It does not support joins, CTEs, or window functions. Use a real database container for those.

run_pipeline uses LocalExecutor regardless of the pipeline configured executor. This is intentional so tests do not depend on external infrastructure.

18. EXAMPLE: RETRY AND CIRCUIT BREAKER

from nimbusflow.core import Pipeline, task
from nimbusflow.retry import CircuitBreaker, with_circuit_breaker
from nimbusflow.connectors.http import HttpConnector

breaker = CircuitBreaker(failure_threshold=3, recovery_timeout=15.0)
http = HttpConnector(base_url="https://api.example.com", timeout=10.0, max_retries=0)

@task(retries=2, backoff="exponential", backoff_base=2.0)
@with_circuit_breaker(breaker)
def fetch_status():
    return http.get("/status").json()

pipeline = Pipeline(name="status_probe", schedule="*/5 * * * *")
pipeline.add(fetch_status)

In this example, @task(retries=2) gives three total attempts. The circuit breaker opens after three consecutive failures. HttpConnector(max_retries=0) means no HTTP-level retries. Task-level retries handle retries. If the breaker opens, CircuitOpenError is raised immediately and is not retried unless included in retry_on.

19. EXAMPLE: POSTGRES TO PARQUET

from nimbusflow.core import Pipeline, task
from nimbusflow.connectors.postgres import PostgresConnector
from nimbusflow.io import ParquetWriter

pg = PostgresConnector(dsn="postgresql://user:pass@localhost/db", pool_size=8)

@task(timeout=600)
def extract(ctx):
    with pg.cursor() as cur:
        cur.execute("SELECT id, status FROM users WHERE status = %s", ("active",))
        return cur.fetchall()

@task
def write(rows):
    ParquetWriter(path="s3://bucket/active_users.parquet", compression="zstd").write(rows)

pipeline = Pipeline(name="pg_to_parquet", schedule="0 3 * * *")
pipeline.add(extract >> write)

ParquetWriter uses zstd compression. brotli raises UnsupportedCodecError. PostgresConnector requires psycopg>=3.1. psycopg2 is not supported.

20. EXAMPLE: KAFKA CONSUMER WITH MANUAL COMMIT

from nimbusflow.core import Pipeline, task
from nimbusflow.connectors.kafka import KafkaConnector

kc = KafkaConnector(
    bootstrap_servers="localhost:9092",
    group_id="nimbusflow-demo",
    auto_offset_reset="earliest",
    enable_auto_commit=False,
    max_poll_records=200,
)

@task(retries=3, backoff="linear", backoff_base=1.0)
def consume(ctx):
    batch = kc.poll(timeout=5.0)
    kc.commit()
    return batch

pipeline = Pipeline(name="kafka_demo")
pipeline.add(consume)

enable_auto_commit=False means NimbusFlow commits offsets after the stage succeeds. max_poll_records=200 overrides the default of 500. The Kafka connector requires the kafka extra and is not available on Python 3.12 via the all extra.

22. GLOSSARY

Pipeline: a DAG of tasks with a name and optional schedule.
Task: a callable decorated with @task.
Context: run metadata injected into a task parameter named ctx.
Executor: component that runs tasks. Values are LocalExecutor, ProcessExecutor, RemoteExecutor.
RetryPolicy: retry configuration with max_attempts counting total attempts.
CircuitBreaker: failure threshold and recovery timeout wrapper.
NDJSON: newline-delimited JSON.
Control plane: NimbusFlow Enterprise service for remote execution.
Extra: optional dependency group installed with pip extras.
